<objective>
Record a decision for each of D1-D5 and restate the five properties they affect, so the
refinement and trace phases quote a decided behaviour instead of inferring one.

Purpose: DEV-01 to DEV-04 and ROADMAP criterion 5. Five places in the catalog note that the
code and the spec disagree, and five property statements are therefore ambiguous about which
side they assert. PROP-30 reads differently depending on whether a future-epoch message is an
error; PROP-43 depends on whether MAC failure aborts the session. Phase 4 cannot state
REFINE-01 to REFINE-05 until this is settled.
Output: one edited file. No Lean, no `src/`.
</objective>

<decision_posture>
Every decision is **Provisional**, dated, with **the code as implemented authoritative**.
Phase 1 does not wait on Signal and does not speak for Signal. The outward-facing
five-question note is deferred to v2 (DEV-05).

This is a recorded project decision, not a claim that the code is right. Each Decision cell
must say so in its own words, so a reader cannot mistake a provisional row for a ruling. If
Signal later rules differently, restating the affected property is a new phase insertion -
which is exactly why the statements below are written to be quotable and locatable.
</decision_posture>
